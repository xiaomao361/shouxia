# 图文取件码识别回归修正（本地，未分发）

2026-10-17 用户报告苹果审核通过，但此前可用的图文识别出现漏识别；提供极兔提货短信截图。本轮在用户授权下修改源码和验证，未提交、发布、安装或操作 UI。首轮保留既有 1.2.7（23）版本配置；用户后续指定热修版本 **1.2.8（24）**，继续完成数字角色与无标签候选复查。以下为首轮定位证据，最终行为和验证以[1.2.8 热修记录](../../app-store/HOTFIX_1.2.8_24.md)为准。

## 已证实原因

1. 1.2.7 将旧版任意数字回退改为明确标签/取件句式约束，降低误收数字的同时收窄了覆盖范围。规则遗漏“凭某码提货”，导致人工正确转录的文本在手动、自动、分享文字、图片行四入口均失败。四入口共用核心，因此同时受影响。
2. 原图在 macOS Vision（accurate、zh-Hans/en-US、关闭语言纠正、top1，沿用源码排序及完整几何）中读出了完整取件码、地点与“提货”，修复前后续提取仍报 noPickupCode。该样本主要失败在解析层。Vision 将品牌“极兔”读成“极免”，品牌另有 OCR 错误。
3. 同类构造输入发现“提取包裹”“取件密码”“提取码”“凭：某码取件”漏识别；数字内部换行可能使码前缀成为正常结果；有一条成功时，无标签失败通知可能不进入遗漏计数。
4. 既有研究集是参与规则开发的样本，不能证明真实用户分布上的准确率或召回率提升。开发集回放、编译和主机测试通过均不足以作为整体效果验收。

## 本轮修正

- 补齐上述明确句式和标签；共用标签常量同步用于旧码排除与地点绑定。
- 疑似数字续行标记为截断，图片/分享核对页默认不选；直接文字路径返回 ambiguousCode，避免保存截短码。不会猜测拼码。
- 有取件语境及凭码领取指令、但没有候选码的通知纳入遗漏提示；有效的其他通知继续保留。
- 保留手机号、包裹尾号、遮挡码、旧码、作废码及红包数字排除。品牌未知仍为空，不由近似字猜测承运商。
- 持久测试用替换地点与代码，原图和用户原文仅在本机临时目录验证，不加入仓库。

## 验证

- 145 项主机测试，0 失败；包括新增跨入口句式、旧码/数字角色、截断保护及部分成功提示检查。补丁前的首个新增正例已复现 missingCode。
- 既有 43 条研究输入及 7 条复核输入，修复前后完整回放 JSON 无变化；证明既有样本输出稳定，不代表未见模板没有回退。
- 用户原文四入口均得到完整代码和地点。原图 → macOS Vision → 当前图片提取器得到 `11-4-0021` 与 `明光市爱福家园快递站`；品牌为空，原因是 OCR 原始输出“极免”。macOS 探针不能替代 iPhone UIKit 路径和交互验收。
- iOS Simulator generic Debug 非签名构建成功，覆盖主 App、分享扩展和小组件；未启动模拟器或 App。

## 验收边界

当前只确认以上缺陷修正；不称整体识别率已恢复。OCR 字符替换、其他标签/句式、复杂卡片边界与更多真实模板仍需独立样本验证。后续效果评估应同时报告正确提取、漏识别、错误提取、截断/待核对和多通知完整性，并比较旧版、新版及修复版。参与修补的样本作为回归集，不能再充当独立效果评估集。真机原图与真实输入验收尚待完成，新补丁未进入用户设备。
