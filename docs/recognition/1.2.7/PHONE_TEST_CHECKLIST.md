# 1.2.7 手机测试清单（当前22）

先检查原有待取、历史记录是否正常，再测试新增识别。优先用之前识别错误的真实短信和截图；下面文本是补充构造样例，不代表真实 OCR 准确率。

## 第一轮：核心识别（优先）

1. **真实错例**：挑 3～5 条之前出错的短信/截图，通过原来使用的入口导入。逐条对照完整取件码、快递站名称、快递公司。手机号、尾号、运单号、时间不能混进取件码；未知信息允许留空。菜鸟、丰巢等取件服务不代表承运快递公司已被识别。
2. **文字与图片一致性**：同一通知分别分享文字、分享截图或从 App 识图，比较码、地点与品牌。图片额外检查换行、字母、前导零、连字符。先在核对页比较；保存后的再次导入可能被去重。
3. **多条通知**：一张图含多条通知，或一次分享多张图（最多五张）。记录数和地点应一一对应；遮挡、未识别的通知应提示，不应把上一条地点套给下一条。

## 第二轮：风险提示与更正

从支持文字分享的应用选中文字，分享给收下，检查核对页：

```text
原取件码1234已失效，新取件码5678，请到南门便利店领取。
```

预期只保留 5678，地点为南门便利店。

```text
取件码1234或取件码5678，请确认后领取。
```

预期两项都不默认选中，需要手动确定；同组选中一个后不能同时保存另一个。直接自动导入应提示歧义，不能直接新增两件。

```text
【丰巢】取件码8291…，已到北门丰巢柜
```

预期提示可能不完整，默认不选；先点更正，依据完整原通知补全后再保存。没有完整原文时不要猜码。

更正时检查：修改后取消，原值不变；输入非法码不能应用；有效更正能保存，记录里的码和地点与更正后相同。从1.2.7（22）起，低清晰度或地点缺失候选也默认选中并保留提示；截断、备选码和冲突地点仍须先确认。

```text
活动奖励已到账，请点击领取 1234 积分。
```

预期不能新增取件记录。也可补测登录验证码、手机号、运单号、地址数字等无取件码文本。

## 第三轮：保存与已有功能

- 核对页取消不新增；保存后手动打开收下，所选记录出现，未选记录不出现。
- App 不运行时从其他应用分享并保存，再手动打开收下，应接收到记录。
- 同一通知重复保存，不应重复新增；相同码但不同快递站的两件不能误合并。上下文缺失时目前保守处理，可能保留额外记录。
- 检查原有记录、标记已取、历史和小组件基本功能。

## 反馈格式

遇到错误，保留原短信或截图，并说明：导入入口、实际结果、正确的码/站点/快递公司。涉及姓名、手机号或地址可先遮挡；尽量保留出错字段周围的上下文。

## 验证边界

此前 129 项主机测试通过，197 次解析回放完成，iOS Release 和模拟器测试源码编译通过。这些不代表本清单的手机交互、真实截图 OCR 或 iOS 16 实际运行已经验收。无需故意制造磁盘满等保存失败；出现失败时保留提示与操作步骤。
