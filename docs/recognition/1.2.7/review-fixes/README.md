# 1.2.7 识别复核问题修复

2026-10-15。接续首轮实现与7组构造输入复核；保持版本1.2.7，工程build17未变，分发测试包时再递增。本轮未commit/push/安装/上传，未操作App、浏览器或Simulator UI。

## 已完成

1. **领取语境门槛。** 隐式“凭…领取 / 领取…”需要快递/包裹/取件/驿站等上下文；候选旁的积分、红包、优惠券、金额等角色不采纳。完整通知不再因为有“领取+数字”就成为取件通知。人工主动输入的完整裸码仍保留。
2. **失败块也有边界。** 分段独立于提码是否成功；先前码被遮挡，后一个标签仍可开始新通知，不继承前块地点，保留遗漏计数。已失效/旧码引用本身不作为“新通知漏识别”计数。
3. **码之间的关系。** 明确旧码、失效码不进入待取；更正/更新/改为的新码替代最近旧候选。数字地址更正与URL路径不参与码替换/备选提取。备选关系支持省略或重复码标签，自动粘贴/短信返回歧义而不直接写入，图片/分享进入核对且只能选择同组一个候选。显式多包裹码列表仍保留多个码。
4. **截断与地点歧义。** `…`、`...`、项目符号等可疑截断在可用候选长度内标记待更正，不能默认选中或直接保存。码太短、星号遮挡等仍可能没有可用候选，应换完整文本/清晰图。两码之间归属不明的地点保留缺失；明确冲突区别于普通缺失，不自动用常用地点覆盖冲突。
5. **统一核对状态。** App截图核对和分享扩展使用同一`PickupCandidateReview`。只有明确标签、地点存在、字符置信度达到0.8且无风险的候选默认选中；0.8是保守交互门槛，不是校准的正确率。其余需要主动选择或更正，风险项显示文字说明，备选组互斥；截断/地点歧义必须先应用更正。
6. **保存前编辑。** 两处核对页可更正码和地点，使用本地草稿。取消关闭编辑且不应用草稿；应用前统一验证，失败保留原条目、稳定ID、选择和输入来源。编辑成已勾选重复项会被拒绝，同码异地仍可分别保留。编辑空地点时明确告知后续常用地点规则。
7. **保存边界。** App的整批选择先验证、一次落盘，不逐条提交；经过核对的字段按结构保存，不重新当短信解析。保存失败返回false，核对页保持打开。分享扩展保留原先原子队列及重试机制；编辑后的文字/图片输入来源通过条目保存。码、地点、品牌、输入来源之外的备选分组/完整通知不进入队列。

更正按钮补充44×44触控区域与名称，风险提示包含文字/图标，采用原生Toggle/Form/Sheet。没有执行触控、VoiceOver、键盘或视觉走查，因此这些不是交互验收通过的声明。
