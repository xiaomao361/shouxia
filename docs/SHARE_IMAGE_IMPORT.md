# 从系统分享菜单收下文字与截图

2026-10-14 当前开发候选 **1.2.7 (17)**：文字与截图共用现有分享入口，签名开发包已覆盖安装到 iPhone 14 Pro / iOS 27.0.1，应用列表读回 1.2.7 / 17 / builtByDeveloper=true。用户一般试用图片分享反馈正常；新增文字流程仍待用户手动检查。**暂不提交 TestFlight 或审核**。

## 使用与页面边界

在提供系统文字/图片分享的 App 中，选择取件文字或一至五张截图 → 分享 → 收下 → 核对勾选 → 保存 → 完成。首次可能在“更多”里找到收下。来源 App 是否提供分享入口由它决定，不承诺微信任意文字都支持；没有入口时继续使用既有粘贴或选图。

不新增首页按钮、模式切换或“请人帮取”选项。图片与文字混合输入仍共用一页核对、按取件码去重，保留字段更完整的候选。

分享确认后先保存到设备本地接收队列；下次启动收下或回到前台自动加入待取，并在此时刷新小组件和已有实时活动。无需再次确认，不强制从分享扩展打开主 App；保存不表示小组件已即时更新。

## 本地处理与数据

- 图片用 Apple Vision 逐张本机 OCR，最多五张，单张输入最多 20 MiB，识别前最长边缩到 2400 像素。
- 文字读取系统 text attachment；纯文字宿主可用 attributedContentText。最多十段、每段最多 64 KiB；不读取其他 App 内容或网页 URL 内容。
- 完整通知需明确取件码标签；主动分享的一整段独立取件码可识别。无关句子中的孤立数字、手机号或纯英文词不兜底为取件码。
- 多条带标签通知分别处理地点；多行单条通知保留自己的地点。跨通知缺失地点明确未识别，不借用另一条的地点。入库时沿用常用地点设置，并保留常用地点来源标记。
- 只保存勾选的码、最小地点/平台及来源，不保存图片、完整分享原文、OCR 全文或未选中的候选。
- 新文字来源显示“文字分享”；图片仍为“图片识别”。旧队列缺失 source 时保持图片语义；新来源只接受这两类。

## 入库与失败

App Group `group.com.zhouwei.shouxia` 的 `image-share-inbox-v1` 仍是最小字段队列，不迁移或删除旧队列。每批一份原子写入文件，最多 50 批，单文件最多 64 KiB。原 PickupRepository 保持取件数据库唯一写入入口。

主 App 校验每批后一次原子入库；成功或按既有规则确认重复才移除队列文件。无法读取/写入数据库、候选无效或移除失败时保留可重试状态，并显示未接收提示；其他有效批次继续。部分图片/文字识别失败明确显示遗漏数量，全部失败不能保存；取消和未勾选内容不入队。

同批记录共用批次标识，并沿用待取码跨短信、粘贴、相册的去重。已保存记录的稳定批次指纹支持确认移除失败后的重试；旧件完成后新的分享批次可复用短码。
