# 系统分享导入

## 使用方式

在支持系统文字或图片分享的应用中，选择取件文字或 1 至 5 张截图，通过分享菜单选择“收下”，核对取件码与地点后保存。首次使用时，入口可能位于“更多”中。来源应用是否提供分享菜单由其自身决定；没有入口时可使用主动粘贴或相册导入。

文字与图片混合输入共用核对页。普通可添加候选默认选中，可取消不需要的项目；低清晰度和缺地点保留提示，截断码、替代码、冲突地点和数字用途歧义需确认或更正。

确认后，扩展将最小取件字段写入本地队列。主应用下次启动或回到前台时接收，随后刷新小组件与已有实时活动。扩展不强制打开主应用；扩展保存成功不表示小组件已即时刷新。

## 输入限制

| 类型 | 限制与处理 |
| --- | --- |
| 图片 | 最多 5 张，单张最多 20 MiB；识别前最长边缩至 2400 像素，使用 Apple Vision 在本机 OCR |
| 文字 | 最多 10 段，每段最多 64 KiB；读取系统文字附件或纯文字宿主提供的内容 |
| 接收队列 | 最多 50 批，每批文件最多 64 KiB，原子写入 |

扩展不请求网页 URL 内容。文字、图片和候选字段均经过数量、长度与格式校验。分享激活规则使用版本 2 和严格类型匹配，仅声明文字及图片能力。

## 识别与持久化

完整通知根据标签、凭码句式和明确取件上下文提取候选；主动分享的独立码也可识别。电话、日期及其他数字按用途判断，不从长号码中截取合法子串。

多条通知分别关联地点；地点缺失时不借用另一通知的信息。同码不同地点或快递信息的候选保留供核对，缺少上下文时不直接合并。常用地点仅按主应用的导入设置补全，并标明来源。

只保存所选候选的取件码、最小地点、平台及来源，不保存图片、完整分享原文、OCR 全文或未选内容。新文字来源为“文字分享”，图片来源为“图片识别”；旧队列缺失来源字段时按图片处理。

## 队列与失败处理

共享容器为 `group.com.zhouwei.shouxia`，队列目录为 `image-share-inbox-v1`。分享扩展只写队列，`PickupRepository` 是主取件记录的统一写入入口。

主应用校验后整批原子入库，成功或确认重复后移除队列文件。数据库读取、写入、候选校验或队列移除失败时保留可重试状态，并提示未接收；其他有效批次可继续处理。稳定批次指纹避免移除失败后的重试重复添加。

部分输入识别失败时保留有效结果并提示遗漏数量；全部失败不允许保存。取消不入队，迟到的异步识别结果不应恢复已取消的流程。相关检查见 `PickupImageShareTests.swift` 与[识别回归](DEVELOPMENT.md#识别回归)。
