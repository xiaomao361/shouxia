# 从系统分享菜单收下截图

2026-10-14：本地实现，尚未安装、上传或完成真机分享验收。本功能不在 2026-10-13 上传的 1.2.6 (16) 中；发布前需分配新的构建号。

## 使用

在照片或支持系统图片分享的 App 中，选择一至五张取件截图 → 系统分享 → 收下 → 核对并勾选取件码 → 保存 → 完成。首次可能需要在分享列表的“更多”中找到收下。是否提供系统分享入口由来源 App 决定，不能承诺从任意微信消息直接进入。

分享确认后先保存在设备的本地接收队列；下次启动收下或切回前台时自动加入待取，届时刷新小组件和已有实时活动。无需再次选图或确认，不强制从分享扩展打开主 App。分享保存不是主 App 入库或小组件已经更新，界面明确提示这个时间边界。

只保存所选取件码、识别地点和平台，不保存图片、OCR 全文或未选中的候选。缺失地点使用接收时的常用取件点，并沿用“常用地点”来源标记。图片在扩展进程内逐张缩小并用 Apple Vision 识别，跨图重复码合并；部分失败明确提示失败张数，全部失败不能保存。扩展不需要照片库授权、外部接口或云服务。

## 数据与失败处理

- 新增 `ShouxiaShare` 系统分享扩展，最低 iOS 16；系统激活规则与运行检查均限制为最多五张图片。
- App Group `group.com.zhouwei.shouxia` 中的 `image-share-inbox-v1` 只存最小候选批次。每批一个原子写入文件，最多 50 个待接收批次，单文件最多 64 KiB；图片输入最多 20 MiB，OCR 前最长边缩到 2400 像素。
- 扩展只写接收队列；原 `PickupRepository` 仍是取件数据库的唯一写入入口。不迁移原数据库，不复制完整短信，避免扩展与短信导入争抢原文件。
- 主 App 对每批校验后原子入库，成功或按既有规则确认重复才确认移除队列文件。数据库无法读取/写入或候选无效时保留该批次并显示未接收提示；其他有效批次继续处理。
- 来源沿用“图片识别”；一次分享共用批次标识。当前待取码与短信、粘贴、相册导入统一去重；已保存记录带稳定批次指纹，入库后未确认移除造成的重试不重新添加该记录。新批次可在旧件完成后复用短码。
- 地点、平台直接保留 OCR 的最小结构化字段，避免二次文本解析改变地点含义；取消或未勾选的候选不入队。
