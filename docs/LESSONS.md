# 收下 · 产品与技术教训

## 2026-07-24：先证明系统入口，再设计自动化体验

我们曾把“App Intent 能接收一段文字”误当成“快捷指令能在第三方 App 通知到达时自动取得通知正文”，并据此制作了“通知自动收码”的入口和引导。实际边界是：

- iOS 的个人自动化支持“收到信息”触发器，因此 SMS/iMessage 可以作为自动导入入口；
- iOS 没有面向任意第三方 App 通知的通用个人自动化触发器；
- App Intent 只能处理系统或用户明确传入的数据，不能主动读取通知中心；
- 用户已经复制文字后，再手动运行快捷指令并粘贴，不比 App 内一键粘贴更省事。

以后涉及系统集成时，按以下顺序推进：

1. 先在当前系统版本和真机上证明触发器存在；
2. 再证明完整数据能够传入，并验证后台、权限和确认行为；
3. 最后才制作用户引导、完成状态和“自动”相关文案；
4. 未经端到端验证的能力只能标为技术探针，不能进入产品承诺。

本次决定：删除第三方通知自动化方案，仅保留“收到信息”个人自动化和用户主动粘贴两条真实入口。
