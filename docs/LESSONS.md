# 收下 · 产品与技术教训

## 2026-07-30：自动化显示运行，不等于正文已经传入

短信个人自动化可以正常触发，“保存取件短信”App Intent 也可以被系统发现，但这两项都不能证明短信正文已经进入参数。

真机验证确认的可靠链路是：

```text
“信息”个人自动化
→ 运行普通快捷指令“收下自动收码”
→ 从“快捷指令输入”中获取文本
→ 将文本明确连接到“保存取件短信”的“短信内容”
→ 后台解析并持久化
```

原四步引导让用户直接在个人自动化里选择 App 动作，遗漏了输入转换和变量连接。结果可能是自动化看起来已经运行，但 App 没有得到完整正文。

以后排查类似系统自动化时，按证据层级区分：

1. App Intent 已注册；
2. 自动化已触发；
3. 输入内容字段获得了真实数据；
4. App 在预期运行状态下完成业务逻辑；
5. 结果已经持久化并可在 App 中核对。

排查“没有自动添加”时，应先检查输入内容字段和变量连接，再检查触发器与权限。

## 2026-07-30：自己的自动收，别人托的随手收

菜鸟、淘宝、京东等平台已经能管理大量属于用户自己的包裹。“收下”的差异不在于重新做物流平台，而在于为实际去取快递的人统一接住两类信息：

- 发到这台 iPhone 的自己的取件短信，通过系统自动化进入；
- 家人朋友临时发来的取件文字或截图，通过主动粘贴和本机识图进入。

两类信息最终汇入同一个待取列表。第一版仍是单机个人工具，“别人托取”不等于家庭账号、远程共享或云同步。

## 2026-07-24：先证明系统入口，再设计自动化体验

我们曾把“App Intent 能接收一段文字”误当成“快捷指令能在第三方 App 通知到达时自动取得通知正文”，并据此制作了“通知自动收码”的入口和引导。实际边界是：

- iOS 的个人自动化支持“收到信息”触发器，因此 SMS/iMessage 可以作为自动导入入口；
- iOS 没有面向任意第三方 App 通知的通用个人自动化触发器；
- App Intent 只能处理系统或用户明确传入的数据，不能主动读取通知中心；
- 用户已经复制文字后，再手动运行快捷指令并粘贴，不比 App 内一键粘贴更省事。

以后涉及系统集成时，按以下顺序推进：

1. 先在当前系统版本和真机上证明触发器存在；
2. 再证明完整数据能够传入，并验证后台、权限和确认行为；
3. 最后才制作用户引导、完成状态和“自动”相关文案；
4. 未经端到端验证的能力只能标为技术探针，不能进入产品承诺。

本次决定：删除第三方通知自动化方案，仅保留“收到信息”个人自动化和用户主动粘贴两条真实入口。
