# 小组件与实时活动

## 共享快照

主应用通过 `PickupSurfacePublisher` 向 App Group 发布最小待取快照。`Shared/PickupSurfaceSnapshot.swift` 定义读取契约，包含取件码、地点、地点来源标记、记录标识和更新时间，不包含短信原文或完整历史。

小组件读取快照，不写主数据库。快照不可用、过期和无待取记录应分别处理；主记录保存成功但展示刷新失败时，应保留两种结果的区别。

## 小组件

- 桌面小组件提供小号与中号布局，锁屏小组件只显示待取件数。
- iOS 16 使用 `StaticConfiguration` 展示全部待取；iOS 17 及以上使用 `AppIntentConfiguration`，支持地点筛选和隐藏码。
- 刷新由系统调度，可能延迟；扩展接收分享后，需主应用入库并发布快照才反映新记录。

## 实时活动

实时活动由用户在“设置 → 锁屏与灵动岛”主动开启，默认关闭，并受系统权限限制。锁屏可能展示取件码，灵动岛还要求兼容硬件。

应用在前台启动活动，本地记录变化后更新已有活动，不使用推送后端。每次会话最长 8 小时；到期或被移除后，保持设置开启并再次进入应用前台可恢复展示。结束不会完成或删除包裹。

| 系统 | 实现 |
| --- | --- |
| iOS 16.0 | 无实时活动，设置页说明系统要求 |
| iOS 16.1 | 使用对应版本的请求、更新与结束 API，并以会话到期时间判断有效性 |
| iOS 16.2 及以上 | 使用 `ActivityContent` 及系统 stale 状态 |

主应用在启动、回到前台及前台主题变化时同步外观。应用关闭期间切换系统主题后，需再次打开收下同步实时活动外观；息屏低亮度采用深色显示。活动状态与最小运行诊断保存在本机，不增加远程通信。

## 交接文件

工程为 `.shouxia` 文件声明类型及图标，接收时执行版本、数量、字段长度和取件码格式校验，预览确认后导入。文件图标只表示文件类型，不表示文件可信或已成功入库。

## 验证

`PickupSurfaceTests.swift` 和 `PickupActivityTests.swift` 检查快照、失效、会话及版本能力逻辑，可通过主机测试执行。系统刷新时机、锁屏显示、灵动岛布局和明暗切换需在对应设备与系统上单独验证，构建通过不能替代这些检查。
