# 收下 1.2.0 (6) TestFlight 测试说明

Status: Uploaded — 2026-08-27 已完成自动化测试、Release Archive 与 App Store Connect 上传；Apple 已返回 `Uploaded package is processing`，尚未验证 TestFlight 处理完成或外部测试。

## Beta App Description

收下是给实际去取快递的人使用的本地优先取件码收件箱。自己的取件短信可以通过系统自动化进入，他人托取的文字或连续截图可以通过主动粘贴、本机识别进入。需要请别人代取时，可以批量发送“收下交接包”；分享成功后，发送方本侧流程结束并标记为“交给别人”，不需要等待或追踪对方状态。

## What to Test

本轮重点验证“交给别人”流程，以及上一轮界面和取件体验改版。

### 交给别人

1. 选择一件或多件待取记录，通过微信、信息或 AirDrop 发送“收下交接包”；分享完成后，确认所选记录离开待取列表。
2. 打开“收下记录”，确认这些记录标记为“交给别人”，而不是“已取到”。将记录恢复为待取后，确认交接标记和完成时间均被清除。
3. 取消系统分享，确认所选记录仍保留在待取列表。
4. 接收方打开交接包，预览并确认导入；确认记录正常进入待取列表，重复打开同一交接包不会重复添加。

### 界面与取件流程

5. 在待取列表中上下滚动，并从卡片任意位置向右全滑“收下”；确认滚动顺畅，不会误触完成，完成后可在五秒内撤销。
6. 轻点卡片进入大字取件模式；同地点或同批导入有多件时左右切换，点击“已取到，收下”后自动进入下一件，最后一件完成后返回首页。
7. 在大字取件模式中更正取件码或地点，确认修改后仍能正常完成和恢复。
8. 检查首页的“粘贴取件信息”和“识别取件截图”入口，确认两个按钮大小、圆角和点击体验一致。
9. 使用较大字体或 VoiceOver 检查待取卡片、大字取件模式、“交给别人”标记和恢复操作，确认内容可读且操作完整。

### 导入与升级

10. 一次选择两至五张有重复内容的物流截图，确认本机识别后相同取件码只保留一条，并可在导入前勾选确认。
11. 设置常用取件点后导入一条缺少地点的信息，确认只补全新记录并显示来源标记，不改变已有记录。
12. 如已开启“打开时识别剪贴板”，分别检查有效取件信息、无关文字和同一内容重复打开；只有新的有效内容应被导入。
13. 从已有版本升级，确认原有待取、已完成和归档记录仍可正常读取。

建议重点反馈：列表滚动或滑动误触、取件状态不正确、重复导入、旧记录丢失，以及较大字体下按钮或文字被截断的问题。

## 已知边界

- “交给别人”只表示发送方责任已经交出，不表示对方已经导入或取件；
- 收下不提供账号、回执、家庭共享或双边状态同步；
- 系统分享取消时不会改变发送方记录；
- 交接包仍只包含取件码、地点、平台和重复导入标识，不包含短信原文、手机号、运单号或商品信息；
- 本 Build 用于 TestFlight 验证，不代表正式 App Store 发布候选已经通过验收。
