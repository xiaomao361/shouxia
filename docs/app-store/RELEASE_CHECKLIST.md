# 发布流程

本清单适用于 TestFlight 与 App Store 构建。每次发布单独记录结果；源码检查、归档、上传、处理、可安装和审核通过是不同状态。

## 版本准备

- [ ] 确定发布范围，更新 [CHANGELOG](../../CHANGELOG.md)、[商店文案](METADATA_ZH_HANS.md)及[审核说明](APP_REVIEW_NOTES.md)。
- [ ] 主应用、分享扩展、小组件的 Debug/Release 版本一致，构建号高于此前分发包。
- [ ] 核对三个 target 的部署目标、Bundle ID、App Group、entitlements 与签名配置。
- [ ] 记录归档源码提交；存在未提交变更时另保存源码清单和哈希。

## 自动验证

- [ ] 执行 `bash scripts/check_recognition.sh`；检查失败、跳过项及覆盖范围。
- [ ] 编译 iOS 应用、扩展与测试源码，记录实际 Xcode/SDK 版本及警告。
- [ ] 检查教程视频、封面和其他资源已打包，扩展不重复包含主应用专用资源。
- [ ] 检查文档链接、隐私清单和演示数据，不提交私人样本、证书或账号信息。

## 设备回归

- [ ] 覆盖升级后待取与历史记录保留，完成、撤销、恢复与删除行为正常。
- [ ] 粘贴、真实截图、系统分享与交接包的导入、取消、重复和失败重试正常。
- [ ] 短信设置与运行符合当前系统版本，真实短信可传入正确正文。
- [ ] 小组件与实时活动的显示、刷新、到期和外观符合说明。
- [ ] 检查大字体、VoiceOver、减少动态效果与明暗模式。
- [ ] 版本涉及设置引导时，由不熟悉该流程的测试者按说明完成配置。

记录设备与系统覆盖，未覆盖版本保持明确，不将单台设备反馈推广为全部系统验收。

## 归档与签名

- [ ] 使用目标源码生成 Release Archive。
- [ ] 读取主应用及两个扩展的实际版本、最低系统版本与 Bundle ID。
- [ ] 核对各 bundle 签名、App Group、描述文件及嵌入关系。
- [ ] 检查应用与 dSYM UUID 匹配，保留符号文件。
- [ ] 归档前后源码与媒体哈希一致；记录产物及使用的 ExportOptions。

本地构建日志、源码清单、归档、dSYM 和上传回执保存在 `.private/releases/<version>-<build>/` 或受控归档目录。审核联系人及凭据不进入公开仓库。

## TestFlight

- [ ] 上传成功，保存明确的成功回执与构建标识；失败尝试单独记录。
- [ ] 在 App Store Connect 确认处理完成且没有阻断问题。
- [ ] 确认目标测试组可见，并可通过 TestFlight 安装。
- [ ] 填写测试说明与反馈联系方式，按需要配置外部测试审核。
- [ ] 完成覆盖更新及关键流程回归，记录问题与未覆盖项。

`Upload succeeded` 或 `Uploaded package is processing` 只表示上传接收，不表示已可安装或通过审核。

## App Store

- [ ] 核对待审版本、构建、更新说明、审核说明及截图与实际功能一致。
- [ ] 核对隐私、年龄分级、销售范围和联系人字段。
- [ ] 提交审核，处理审核反馈。
- [ ] 审核通过后按选定方式发布，并确认产品页与可下载版本。

代码推送、TestFlight 上传与正式发布分别核验。公开版本说明集中描述用户可见变化，逐次上传和安装回执留在发行档案。
