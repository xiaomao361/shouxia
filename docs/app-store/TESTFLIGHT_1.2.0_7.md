# 收下 1.2.0 (7) TestFlight 测试说明

Status: Candidate — 已完成自动化测试、Debug 真机构建与安装，正在准备 Release Archive 和 TestFlight 上传。

## Beta App Description

收下是给实际去取快递的人使用的本地优先取件码收件箱。自己的取件短信可以通过系统自动化进入，他人托取的文字或连续截图可以通过主动粘贴、本机识别进入。需要请别人代取时，可以批量发送“收下交接包”；分享成功后，发送方本侧流程结束并标记为“交给别人”，不需要等待或追踪对方状态。

## What to Test

本轮重点验证剪贴板自动识别的启动体验、“交给别人”流程，以及上一轮界面和取件体验改版。

### 剪贴板自动识别

1. 在“隐私与关于 → 导入设置”开启“打开时识别剪贴板”，确保首页已有一条或多条待取记录。
2. 从其他 App 复制一段新的内容后重新打开“收下”；确认已有取件码立即显示，不会先闪出空状态。
3. 如系统显示粘贴授权框，确认授权框背后仍能看到已有记录；允许后，新的有效取件信息应随后加入。
4. 分别复制无关文字和之前处理过的内容；确认无关文字保持安静，同一内容不会重复导入。

### 交给别人

5. 选择一件或多件待取记录，通过微信、信息或 AirDrop 发送“收下交接包”；分享完成后，确认所选记录离开待取列表。
6. 打开“收下记录”，确认这些记录标记为“交给别人”，而不是“已取到”。将记录恢复为待取后，确认交接标记和完成时间均被清除。
7. 取消系统分享，确认所选记录仍保留在待取列表。
8. 接收方打开交接包，预览并确认导入；确认记录正常进入待取列表，重复打开同一交接包不会重复添加。

### 界面、取件与导入

9. 在待取列表中上下滚动，并从卡片任意位置向右全滑“收下”；确认滚动顺畅，不会误触完成，完成后可在五秒内撤销。
10. 轻点卡片进入大字取件模式；检查多件切换、连续完成，以及取件码和地点更正。
11. 检查“粘贴取件信息”和“识别取件截图”两个入口的大小、圆角和点击体验；一次选择多张有重复内容的截图，确认相同取件码只保留一条。
12. 从已有版本升级，确认原有待取、已完成和归档记录仍可正常读取。

建议重点反馈：打开 App 时已有记录是否闪空、列表滚动或滑动误触、取件状态不正确、重复导入、旧记录丢失，以及较大字体下按钮或文字被截断的问题。

## 已知边界

- “交给别人”只表示发送方责任已经交出，不表示对方已经导入或取件；
- 收下不提供账号、回执、家庭共享或双边状态同步；
- 系统分享取消时不会改变发送方记录；
- 交接包仍只包含取件码、地点、平台和重复导入标识，不包含短信原文、手机号、运单号或商品信息；
- 本 Build 用于 TestFlight 验证，不代表正式 App Store 发布候选已经通过验收。
