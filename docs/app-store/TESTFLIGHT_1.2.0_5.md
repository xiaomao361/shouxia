# 收下 1.2.0 (5) TestFlight 测试说明

Status: Draft — 当前源码候选已完成自动化测试、模拟器构建、本地 Release Archive 和开发包真机安装，正在继续日常真机验收；尚未上传 App Store Connect。

## Beta App Description

收下是给实际去取快递的人使用的本地优先取件码收件箱。自己的取件短信可以通过系统自动化进入，他人托取的文字或连续截图可以通过主动粘贴、本机多图识别或用户明确开启后的前台剪贴板识别进入。到了取件现场，可以用大字查看取件码并连续完成同地点或同批包裹。所有取件信息和解析结果只保存在本机。

## What to Test

本轮优先验证 1.2 新增和重做的取件现场、批量导入与纠错流程：

1. 在 0、1、3、10 条以上待取记录下滚动首页，从卡片主体、文字和边缘起手都应顺畅；
2. 向右全滑完成一件，确认卡片轻微下沉、缩小并淡出，列表补位且五秒内可以撤销；
3. 进入大字取件模式，完成当前包裹后自动进入同地点或同批下一件，最后一件完成后正确返回；
4. 更正取件码和地点，确认修改后展示正确，原通知重复导入仍会被拦截；
5. 一次选择两至五张含重叠内容的真实物流截图，确认本机 OCR、跨图去重、候选确认和同批连续取件；
6. 设置常用取件点，确认只补全之后导入且地点缺失的记录，旧记录不被改写；
7. 开启“打开时识别剪贴板”，分别验证首次系统授权、有效取件文字、无关文字、相同内容不重复和关闭状态；
8. 验证 App 未启动时“信息自动化 → 收下自动收码 → App Intent”仍能保存完整短信正文；
9. 使用 VoiceOver 的“收下”自定义动作完成取件，并在“减少动态效果”开启时确认只有简短淡出；
10. 从 App Store `1.0` 或已有 TestFlight 版本升级，确认本地待取和历史记录保留。

## 反馈请包含

- iPhone 型号与 iOS 版本；
- 问题发生前的入口：短信自动化、粘贴、剪贴板自动识别、图片识别或交接包；
- 待取记录数量，以及是否属于同一地点或同批导入；
- 可以稳定复现的操作步骤和预期结果；
- 是否开启 VoiceOver、“减少动态效果”或较大字体；
- 不含真实手机号、地址或取件码的脱敏截图或录屏。

## 已知边界

- 收下不能读取短信历史，也不能替用户创建或查询个人自动化；
- 不读取支付宝或其他第三方 App 的通知中心正文；
- 多图识别使用系统照片选择器和 Apple Vision 本机 OCR，原图不会保存在收下中；
- 前台剪贴板识别默认关闭，只在用户开启、App 进入前台且剪贴板发生变化时尝试；
- 同批分组是一次导入的本地关系，不是云同步或物流追踪；
- 本 Build 用于 TestFlight 验证，不代表正式 App Store 发布候选已经通过验收。
