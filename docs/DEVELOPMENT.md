# 收下开发与验证

## 当前实现

首个纵向薄切片已经包含：

- SwiftUI 单页待取列表；
- 用户主动触发的系统 `PasteButton`，用于读取刚从短信或购物平台复制的正文；
- 本地确定性解析，提取取件码、地点和来源平台；
- 基于规范化原文 SHA-256 的重复导入保护；
- 本地 JSON 持久化；
- 向右滑动“收下”、简化完成动画和五秒撤销；
- 带录入时间和收下时间的记录页；
- 记录可重新设为待取或归档，归档可恢复；
- 只有归档页允许二次确认后永久删除，不设置废纸篓；
- “添加取件信息”App Intent，可接收一段通知文本并在后台导入；
- 菜鸟、丰巢、京东、邮政、快递超市等样本测试。

## 三个首版入口

### 1. 从短信快速复制

在短信中复制完整通知，打开“收下”，点击主页面的系统粘贴按钮。App 不要求手工填写取件码或地点。

### 2. 读取剪贴板

读取必须由用户点击系统粘贴按钮触发。App 不在启动、切回前台或后台时主动读取剪贴板，避免隐私提示和意外导入。

### 3. 购物平台通知

App 暴露一个接收字符串的“添加取件信息”App Intent，作为 iOS 26 快捷指令通知自动化的接收端。预期配置是：

```text
指定购物或物流 App 的通知自动化
→ 可选关键词过滤“取件码 / 驿站 / 丰巢”
→ 将通知自动化提供的通知文字传入“添加取件信息”
```

这个入口必须在真机上逐个平台验证。Apple 已确认 iOS 26 支持按 App 和关键词触发通知自动化，但不同平台是否暴露完整通知文字、取件码数字是否被隐私处理，不能通过模拟器或 App 代码预先保证。App 本身不会、也不能直接监听其他 App 的通知。

## 工程结构

```text
Shouxia/
  App/          App 入口
  Features/     主列表与页面状态
  Models/       取件记录和导入结果
  Services/     解析器与本地持久化
  Intents/      系统“添加取件信息”动作
ShouxiaTests/   解析与去重测试
```

UI、剪贴板和 App Intent 共用同一个 `PickupRepository`，避免三个入口产生不同的解析和去重行为。

## 本地验证

```bash
xcodebuild test \
  -project Shouxia.xcodeproj \
  -scheme Shouxia \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

真机验证还应覆盖：

- 短信复制后一次点击导入；
- 菜鸟、淘宝、京东、拼多多、丰巢通知自动化；
- 通知只有标题、正文被截断或数字被隐藏；
- 同一包裹重复通知；
- App 未启动时运行 App Intent；
- 完成后立即撤销；
- 已收下记录重新设为待取；
- 归档、从归档恢复，以及永久删除确认；
- “减少动态效果”和 VoiceOver 的等价操作。

## 正式视觉与完成交互

首版正式页面采用“暖色包裹标签”方向：暖白画布降低待办压力，深松绿建立安静、可信的主层级，暖杏色集中承担完成反馈，取件码保持视觉中心。

待取卡片支持直接向右拖动。越过阈值后松手，卡片会缩成小包裹并落向底部，随后列表自然补位并显示“收下啦”和五秒撤销入口。开启“减少动态效果”时改为短淡出，不播放位移和缩放过程；VoiceOver 用户可通过卡片的“收下”自定义动作完成同一操作。

空状态、完成提示、记录与归档页面复用同一组颜色和文字层级。此前的 Debug Design Lab 已在方案迁移后移除，正式工程只保留一套界面。
