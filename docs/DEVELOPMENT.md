# 收下开发与验证

## 当前实现

首个纵向薄切片已经包含：

- SwiftUI 单页待取列表；
- 用户主动点击的主操作按钮，只在点击后读取刚从短信或购物平台复制的正文；
- 系统照片选择器与本机 Vision OCR，支持从微信等来源保存的物流截图；
- 图片只有一个明确标签结果时直接添加；多个或无标签候选进入勾选确认；
- 图片导入只持久化取件码、地点、平台和必要片段，不保存原图、手机号、运单号或 OCR 全文；
- 本地确定性解析，提取取件码、地点和来源平台；
- 基于规范化原文 SHA-256 的重复导入保护；
- 本地 JSON 持久化；
- 首页会在待取数量变化时，从空状态或有包裹状态的独立文案池中稳定随机一组文案；
- 轻点待取卡片进入取件现场大字模式，同一地点多件可左右切换；
- 向右滑动“收下”、简化完成动画和五秒撤销；
- 带录入时间和收下时间的记录页；
- 记录可重新设为待取或归档，归档可恢复；
- 只有归档页允许二次确认后永久删除，不设置废纸篓；
- “保存取件短信”App Intent，可接收“信息”个人自动化传入的短信正文并在后台导入；
- 首页“开启短信自动收码”入口与四步引导，可打开“快捷指令”App，并明确提示用户进入“自动化”页；
- 通过 `AppShortcutsProvider` 将“保存取件短信”可靠注册到快捷指令动作库；系统可能同时展示一张 App Shortcut 卡片，但它不是产品导入入口，无需用户单独运行；
- 不根据 App Intent 单次运行声称自动化已验证，因为 App 无法判断它是自动触发还是手动运行；
- 菜鸟、丰巢、京东、邮政、快递超市等样本测试。

## 三个首版入口

### 1. 短信个人自动化

App 暴露一个接收字符串的“保存取件短信”App Intent，作为快捷指令“收到信息”个人自动化的接收端。用户需要在系统快捷指令中亲自完成一次配置：

```text
快捷指令底部“自动化” → 右上角“+” → 信息
→ “发件人”保持“任何发件人”
→ “信息包含”设置为“取件”
→ 选择“立即运行”
→ 下一步 → 收下 → “保存取件短信”
→ 若推荐动作中未出现，在底部搜索“保存取件短信”
→ 保存
```

Apple 当前文档确认“信息”触发器可按发送人和“信息包含”过滤，并支持自动运行。但短信正文作为自动化输入传给 App Intent 的完整链路仍以当前系统版本的真机测试为验收依据。

首页始终提供“开启短信自动收码”卡片。按钮只能打开“快捷指令”App，不能直接跳到或代建个人自动化。`AppShortcutsProvider` 只负责让系统可靠发现底层动作，并不创建个人自动化。系统不允许第三方 App 静默创建或查询个人自动化，因此 App 不展示自动化已配置或已验证状态；用户需要用第一条真实短信端到端确认。

### 2. 用户主动粘贴

用户从短信或购物 App 复制完整取件信息，打开“收下”并点击“粘贴通知”。读取必须由用户点击主操作按钮触发；App 不在启动、切回前台或后台时主动读取剪贴板。

第三方 App 通知不是自动化入口。App 不会、也不能读取支付宝、菜鸟、丰巢或其他 App 在通知中心中的内容。手动运行快捷指令后再粘贴，与 App 内一键粘贴相比没有价值，不作为产品路径。

### 3. 相册图片识别

用户可以把微信等 App 收到的物流图片保存到系统相册，打开“收下”后点击“识别图片”，并在系统照片选择器中选择该图。App 使用 Apple Vision 的准确模式在本机识别简体中文与英文，不上传图片，也不申请整库照片访问。

识别器优先查找“取件码、取货码、提货码、领取码”等标签附近的数字和字母组合，避免把运单号、手机号、距离、时间和门牌号当作取件码。只有一个明确标签结果时直接添加；识别到多个结果或只有无标签候选时，先让用户勾选确认。

持久化前会构造只包含取件码、地点和平台的最小文本。原图、OCR 全文、手机号、运单号与商品信息不会写入本地记录。

## 工程结构

```text
Shouxia/
  App/          App 入口
  Features/     主列表与页面状态
  Models/       取件记录和导入结果
  Services/     解析器与本地持久化
  Intents/      系统“保存取件短信”动作
ShouxiaTests/   解析与去重测试
```

UI、剪贴板、图片识别和短信 App Intent 共用同一个 `PickupRepository`，避免不同入口产生不同的解析和去重行为。

## 本地验证

```bash
xcodebuild test \
  -project Shouxia.xcodeproj \
  -scheme Shouxia \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

真机验证还应覆盖：

- “收到信息”自动化将完整短信正文传给“保存取件短信”；
- 关闭“运行前询问”后，App 未启动时也能导入；
- 短信复制后一次点击导入；
- 支付宝、菜鸟、丰巢等第三方通知不会被误导为可自动读取；
- 同一包裹重复通知；
- 取件现场大字模式的单件展示、同地点多件切换和超长取件码缩放；
- 真实微信物流截图的本机 OCR、自动添加、候选确认、去重与隐私裁剪；
- App 未启动时运行 App Intent；
- 完成后立即撤销；
- 已收下记录重新设为待取；
- 归档、从归档恢复，以及永久删除确认；
- “减少动态效果”和 VoiceOver 的等价操作。

## 正式视觉与完成交互

正式页面采用“晚风杏桃”方向：天空浅蓝画布与两处低对比环境光提供呼吸感，云白纸面承接信息，杏桃色集中承担包裹与完成温度，薄荷色只负责行动和微风提示。完整的变量、品牌资产、组件、关键状态和动效节拍保存在 [Figma v2](https://www.figma.com/design/fjQN8yRyNkYPqMUcL9I6B2)。

待取卡片支持直接向右拖动。越过阈值时先给出触感与薄荷柔光确认；松手后纸签在约 460ms 内轻抬、缩小并向右下归位，随后列表自然补位并显示“轻轻收下了”和五秒撤销入口。开启“减少动态效果”时改为短淡出，不播放位移、缩放或旋转过程；VoiceOver 用户可通过卡片的“收下”自定义动作完成同一操作。

Figma 执行环境中的 SF Pro Rounded 会产生零宽文字，因此设计稿用 Noto Sans SC 作为可见字体桥接；真实 App 仍由 SwiftUI 系统圆体与中文系统回退字体渲染，字体正确性以模拟器和真机为准。

Logo、App Icon、空状态与完成提示统一使用“杏桃包裹 + 云白取件卡”标志，避免用不符合真实包裹尺度的口袋隐喻；可编辑 SVG 源文件保存在 `docs/brand/`。记录与归档页继续复用同一组颜色和文字层级。此前的 Debug Design Lab 已在方案迁移后移除，正式工程只保留一套界面。

## App Store 1.0 准备

工程版本已准备为 `1.0.0 (1)`，使用 iPhone-only 配置、工具类别、无透明通道的 1024 × 1024 App Icon，并在生成的 Info.plist 中声明不使用非豁免加密。`Shouxia/Resources/PrivacyInfo.xcprivacy` 声明当前版本不跟踪、不收集数据，也不连接跟踪域名。

App 内“隐私与关于”页面说明本地处理、主动剪贴板读取和短信个人自动化边界。App Store Connect 元数据、隐私政策、支持页、审核说明与提交检查表位于 `docs/app-store/`。隐私政策与支持页在提交前仍必须发布到公开 HTTPS URL，不能用本地 Markdown 路径代替。
