# shouxia

“收下”是一款给实际去取快递的人使用的 iOS 取件码收件箱：自己的取件短信可以通过个人自动化进入，他人托取的文字可以主动粘贴，也可在用户开启后于打开 App 时自动识别发生变化的剪贴板；聊天里连续收到的物流截图可以从相册一次选择最多五张并在本机合并识别。需要请别人代取时，可以把多件待取信息按地点整理成普通文字，预览并复制给未安装收下的人，待取状态不变；也可以发送本地“收下交接包”，系统分享成功结束后标为“交给别人”。App 提取取件码与地点，取件后用一次滑动完成。

App Icon 以“杏桃包裹 + 云白取件卡”为核心图形，直接表达 App 管理的是附着于包裹的取件信息；Logo 与 App 内空状态复用同一套几何语言。

## 设计

- [Figma：收下 · App Design v2](https://www.figma.com/design/fjQN8yRyNkYPqMUcL9I6B2)
- 视觉方向是“晚风杏桃”：天空浅蓝和云白提供呼吸感，杏桃色承担包裹与完成温度，薄荷色只负责行动和微风提示。
- 首页使用系统列表协调纵向滚动与向右全滑完成；完成后纸签轻微下沉、缩小并淡出，由五秒撤销承接，总时长约 460ms；开启“减少动态效果”时仅保留短淡出。
- 可编辑品牌源文件位于 [`docs/brand`](docs/brand)，与 Figma 和 Xcode App Icon 使用相同几何。

## 当前阶段

项目已经建立首个 SwiftUI 纵向薄切片，1.2.6 开发候选的最低部署版本为 iOS 16（旧系统实测待完成）。原始文本会经过本地解析、完整原文指纹与当前待取码双层去重和本地 JSON 存储，再显示为轻量云白纸签；相册图片由 Apple Vision 在本机 OCR，多图候选按取件码去重，只保存取件码、地点、来源和必要片段，不保存原图与无关全文。导入设置可配置只作用于未来记录的常用取件点，以及默认关闭的前台剪贴板自动识别。轻点卡片可进入取件现场大字模式，同地点或同批导入的多个包裹可以左右切换；向右滑动后，卡片会轻微下沉、缩小并淡出。收下记录默认显示最近 30 天，可查看全部、设为待取或确认后永久删除；旧归档记录仍可查看，不自动删除。首页明确区分“自己的取件短信”和“他人托取”两类入口；待取记录可批量生成 `.shouxia` 交接包，系统分享完成后发送方记录离开待取并标记为“交给别人”，接收方打开后预览确认导入。短信自动收码按系统版本引导：先从 iCloud 添加“收下自动收码”，iOS 27 在其中添加“信息”触发器，iOS 17、18、26 另建信息个人自动化并选择立即运行；iOS 16 使用个人自动化，收到短信后需确认运行；首页设置入口支持手动隐藏，首次短信来源导入后只自动隐藏一次，并可从“设置 → 导入设置”恢复。

## 产品边界

- 第一版只解决取件通知的收集、快速查看、完成和轻量记录管理。
- 默认本地处理和存储，不依赖账号、云端或物流平台 API。
- 数据分析和统计留到有真实使用数据后再定义，不进入 1.0。
- 不做物流追踪、家庭共享、聊天机器人、信息流或 Android 客户端。
- 核心验证是近乎无摩擦的录入，以及克制但令人满足的完成体验。

## 1.2.6 开发候选

版本 `1.2.6 (16)` 基于 `1.2.5 (15)` 发布源码，加入 iOS 16 兼容；自动选择一种短信引导。iOS 16 提供显示全部待取的基础小组件，17 及以上保留地点筛选和隐藏码配置；实时活动需要 16.1 及以上及设备/系统授权。解析、记录格式、交接和既有快捷指令标识保持一致。

本地验证与发布前待测项见 [1.2.6 版本说明](docs/app-store/TESTFLIGHT_1.2.6_16.md)。开发包已安装 iPhone 14 Pro（iOS 27.0.1），用户一般试用反馈未发现明显问题。2026-10-13 09:04 +0800 已上传 1.2.6 (16) 至 TestFlight，Apple 已接收并开始处理；处理完成、测试组可见性与16/26运行验证待完成。2026-10-12 用户报告 1.2.5 已提交审核；尚未独立核查 Apple 审核结果。
